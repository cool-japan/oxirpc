# Migrating from tonic to oxirpc

oxirpc is a thin façade over tonic 0.14 that enforces:

- **Pure-Rust TLS** — `rustls` + `rustls-rustcrypto`; never `ring`, `aws-lc-rs`,
  or `native-tls` by default.
- **No protoc** — code generation uses `protox` + `tonic-prost-build` in your
  `build.rs`; no C binary in the PATH needed.
- **COOLJAPAN ecosystem conventions** — workspace-level dependency management,
  explicit feature gating, zero compression-codec FFI on normal edges.

---

## Quick reference

| tonic API | oxirpc equivalent |
|-----------|-------------------|
| `tonic::transport::Server::builder()` | `oxirpc::ServerBuilder::new()` (feature `server`) |
| `tonic::transport::Channel::from_shared(uri)` | `oxirpc::ClientBuilder::new(uri).connect().await?` (feature `client`) |
| `ServerTlsConfig::new().identity(id)` | `oxirpc::tls::server_config(cert_pem, key_pem)?` (feature `tls`) |
| `ClientTlsConfig::new()` | `oxirpc::tls::client_config(roots)?` (feature `tls`) |
| `tonic_reflection::server::Builder` | `oxirpc::reflect::reflection_service_from_static(fds)` (feature `reflect`) |
| `tonic_health::server::health_reporter()` | `oxirpc::health::health_service()` (feature `health`) |
| `tonic_web::GrpcWebLayer` | `oxirpc::web::GrpcWebLayer` (feature `web`) |

## Cargo.toml changes

**Before (raw tonic):**
```toml
[dependencies]
tonic = "0.14"
tonic-health = "0.14"
tonic-reflection = "0.14"
tonic-web = "0.14"

[build-dependencies]
tonic-build = "0.14"
```

**After (oxirpc):**
```toml
[dependencies]
oxirpc = { version = "0.1", features = ["client", "server", "health", "reflect", "web"] }

[build-dependencies]
oxirpc-build = "0.1"
```

## build.rs changes

**Before:**
```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    tonic_build::compile_protos("proto/service.proto")?;
    Ok(())
}
```

**After:**
```rust
fn main() -> Result<(), Box<dyn std::error::Error>> {
    oxirpc_build::compile_protos(&["proto/service.proto"], &["proto/"])?;
    Ok(())
}
```

`oxirpc-build` uses `protox` internally — no `protoc` binary needed.

## Adding health checks

```rust
use oxirpc::health::{health_service, ServingStatus};

#[tokio::main]
async fn main() -> Result<(), Box<dyn std::error::Error>> {
    let addr = "[::1]:50051".parse()?;
    let (health_svc, mut handle) = health_service();

    // Mark your service as serving before accepting connections.
    handle.set_serving("my.Service").await;

    tonic::transport::Server::builder()
        .add_service(health_svc)
        .add_service(MyServiceServer::new(MyServiceImpl))
        .serve(addr)
        .await?;

    Ok(())
}
```

To mark a service as not serving (e.g. during graceful shutdown):
```rust
handle.set_not_serving("my.Service").await;
```

## Interceptors

Three ready-to-use interceptors are provided in `oxirpc::interceptors`.
See the example files in `crates/oxirpc/examples/` for runnable demos.

### Bearer token auth

```rust
use oxirpc::interceptors::BearerAuthInterceptor;
use tonic::service::interceptor;

let auth = BearerAuthInterceptor::new("my-jwt-token");
// Wrap your service:
let svc = interceptor(auth)(MyServiceServer::new(impl));
```

### Request tracing

```rust
use oxirpc::interceptors::TracingInterceptor;
use tonic::service::interceptor;

let tracer = TracingInterceptor;
// Each RPC gets a unique `x-request-id` header injected.
let svc = interceptor(tracer)(MyServiceServer::new(impl));
```

### Deadline propagation

```rust
use oxirpc::interceptors::DeadlineInterceptor;
use std::time::Duration;
use tonic::service::interceptor;

let deadline = DeadlineInterceptor::new(Duration::from_secs(5));
// Injects `grpc-timeout: 5000m` when caller hasn't set a deadline.
let svc = interceptor(deadline)(MyServiceServer::new(impl));
```

## TLS

See the `oxitls` crate for Pure-Rust TLS configuration with `rustls-rustcrypto`.
No `ring`, no `native-tls`, no OpenSSL.

```rust
use oxirpc::tls;
use rustls::RootCertStore;

// Server TLS (from PEM bytes):
let server_cfg = tls::server_config(cert_pem, key_pem)?;

// Client TLS (provide a RootCertStore with trusted CA certificates):
let roots = RootCertStore::empty(); // populate from webpki-roots or self-signed CA for tests
let client_cfg = tls::client_config(roots)?;
```

> **Note:** Wiring these configs directly into tonic's `ServerTlsConfig` /
> `ClientTlsConfig` is deferred pending tonic 1.0 (which will support
> pluggable crypto providers). In the interim, use `tokio-rustls` directly with
> the returned `rustls::ServerConfig` / `rustls::ClientConfig`.

## Server reflection

```rust
use oxirpc::reflect::reflection_service_from_static;

// FDS bytes are generated by oxirpc-build into OUT_DIR.
pub const FILE_DESCRIPTOR_SET: &[u8] = include_bytes!(concat!(env!("OUT_DIR"), "/fds.bin"));

let reflection_svc = reflection_service_from_static(FILE_DESCRIPTOR_SET)?;

tonic::transport::Server::builder()
    .add_service(reflection_svc)
    .add_service(MyServiceServer::new(impl))
    .serve(addr).await?;
```

## gRPC-Web

```rust
use oxirpc::web::GrpcWebLayer;
use tower::ServiceBuilder;

tonic::transport::Server::builder()
    .accept_http1(true)
    .layer(ServiceBuilder::new().layer(GrpcWebLayer::new()))
    .add_service(MyServiceServer::new(impl))
    .serve(addr).await?;
```

## Codegen Backend (Round 7)

`oxirpc-build::Builder::compile()` now uses the native `ServiceCodegen` backend
by default.  This backend emits **service stubs only** (`*_server` / `*_client`
modules) — it does **not** generate prost message types.

Users who relied on a single `compile_protos()` call to generate both message
types and service stubs should either:

1. Add `prost_build` (or `tonic_prost_build`) to their `build.rs` for message
   generation, and use `oxirpc_build::Builder::compile()` for service stubs.
2. Opt into the legacy backend via `features = ["legacy-tonic-codegen"]` in
   their `[build-dependencies]`:

   ```toml
   [build-dependencies]
   oxirpc-build = { version = "0.1", features = ["legacy-tonic-codegen"] }
   ```

The `legacy-tonic-codegen` feature restores the previous tonic-prost-build
all-in-one generation path, including support for `type_attribute`,
`field_attribute`, `btree_map`, `bytes`, `extern_path`, and
`compile_well_known_types`.

## Pure-Rust policy

oxirpc enforces the COOLJAPAN Pure-Rust policy at every build via `deny.toml`
and the `scripts/ffi-audit.sh` script:

```bash
bash scripts/ffi-audit.sh
# FFI audit PASSED
```

No `ring`, `aws-lc-sys`, `openssl-sys`, `native-tls`, or `flate2` on normal
(production) dependency edges. FFI crates are allowed only behind `[dev-dependencies]`
or explicit `Bounded-FFI` feature gates.
